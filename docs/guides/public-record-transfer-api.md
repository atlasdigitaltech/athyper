# Public record-transfer API

The versioned API at `/api/v1/records` uses the same descriptors, collection scope, authorization checks, governed plane adapters, malware scanning, worker jobs, receipts, audit events, and notifications as the interactive list view. It is disabled unless `RECORD_TRANSFER_PUBLIC_API_ENABLED=true`.

The generated OpenAPI 3.1 document is available at `/openapi.json`; filter operations whose IDs begin with `public.v1.records`. Swagger UI is available at `/docs` when API documentation is enabled for the environment.

## Service-account onboarding

1. Create a confidential IAM client for one integration workload. Do not share clients between middleware products or tenants.
2. Grant only the plane and aggregate permissions required, including `records.import` or `records.export` and the published mutation-mode permission. Collection-scope authorization still applies.
3. Obtain a short-lived bearer token with the service account flow. Store the client secret in the platform secret manager and rotate it under the IAM policy.
4. Confirm the target descriptor publishes the requested file format and operation. Studio draft imports require an active change set; Mesh and Neon require their governed scope coordinates.
5. Run a rejected-file test before enabling writes. A client must consume the receipt and error report, not infer success from HTTP `202`.

## Import lifecycle

Use a UUID as `sessionId`. Reusing it with different immutable inputs is rejected.

```text
POST /api/v1/records/{entityCode}/imports
POST /api/v1/records/imports/{sessionId}/file-upload
PUT  <returned presigned upload URL>
POST /api/v1/records/imports/{sessionId}/file-complete
POST /api/v1/records/imports/{sessionId}/validate
POST /api/v1/records/imports/{sessionId}/preview
POST /api/v1/records/imports/{sessionId}/commit
GET  /api/v1/records/imports/{sessionId}
GET  /api/v1/records/imports/{sessionId}/error-report
```

Begin request:

```json
{
  "sessionId": "018f6d2a-1111-7111-8111-111111111111",
  "operation": "upsert",
  "conflictPolicy": "reject",
  "atomicity": "all_or_nothing",
  "scopeCoordinate": { "operatingOrganizationId": "018f6d2a-2222-7222-8222-222222222222" }
}
```

The supported server-side file types are CSV, XLSX, and JSON. Upload the exact declared byte count to the presigned URL, then complete the file with the same `fileName` and `sizeBytes`. Validation may produce a downloadable NDJSON error report. `valid_rows` commits only valid rows; `all_or_nothing` returns `IMPORT_ATOMICITY_REJECTED` when any row is invalid.

## Export lifecycle

```text
POST /api/v1/records/{entityCode}/exports
GET  /api/v1/records/transfers?limit=100
GET  /api/v1/records/exports/{exportRequestId}/download
POST /api/v1/records/exports/{exportRequestId}/cancel
```

```json
{
  "requestId": "018f6d2a-3333-7333-8333-333333333333",
  "filter": {
    "scopeCoordinate": { "networkAccountId": "018f6d2a-4444-7444-8444-444444444444" },
    "filters": [],
    "sort": [{ "field": "updated_at", "direction": "desc" }],
    "_transfer": {
      "format": "xlsx",
      "scope": "filtered",
      "fields": ["code", "display_name", "status"],
      "headings": true,
      "rawCodes": false,
      "isoDates": true,
      "informationSheet": true,
      "fileName": "business-partners"
    }
  }
}
```

CSV, XLSX, JSON, and NDJSON exports are generated by a governed server job. A download URL is short lived; fetch it promptly and verify the terminal receipt.

## Idempotency and recovery

- Supply UUIDs generated by the caller for import `sessionId` and export `requestId`.
- Repeating the same begin/request operation with the same immutable body is safe. Reusing an identifier for different content fails closed.
- Chunk indexes are contiguous and checksum protected. Replaying an identical chunk is safe; changing it is rejected.
- Commit and job delivery are idempotent. Plane adapters enforce their aggregate identity and conflict policy inside the transaction.
- Failed transfers can be requeued with `POST /imports/{id}/restart` or `POST /exports/{id}/restart`. Restart rechecks ownership, current descriptor, scope, and authorization. It is not available for completed or cancelled work.
- Use cancellation only as a forward stop. It never reverses already committed governed writes.

## Quotas and client behavior

The API currently enforces 100 authenticated requests per tenant/principal per minute and 1,000 requests per source per minute. Descriptor limits additionally govern maximum file bytes, rows, and exported records. A `429` response includes the normal rate-limit response metadata; clients should honor it with exponential backoff and jitter. Do not retry validation errors, authorization failures, malware rejection, descriptor changes, or idempotency conflicts without changing the request.

Production clients should persist the transfer ID and terminal receipt, use bounded polling, correlate requests with their platform correlation ID, and alert when a transfer remains queued/running beyond the published operational threshold.

## Queue disruption acceptance

The API no longer reports a transfer as queued when BullMQ/Redis rejects the dispatch. The durable request is moved to `failed` with `TRANSFER_DISPATCH_UNAVAILABLE`, a failure audit/outbox event is written, and the owner can use the governed restart endpoint after recovery.

Use the confirmation-gated harness for a controlled worker or Redis exercise. Each probe is a JSON command array and must assert its own phase-specific expectation. For a worker pause, the during probe should create a transfer and prove it remains durable until the worker resumes. For a Redis pause, the during probe should prove fail-closed behavior; the after probe should restart the failed transfer and prove its receipt, record, audit event, and notification.

```sh
pnpm acceptance:transfer-disruption -- \
  --project athyper-stg --service worker --confirm athyper-stg:worker \
  --before-probe '["node","/secure/probes/transfer-before.mjs"]' \
  --during-probe '["node","/secure/probes/transfer-during-worker-pause.mjs"]' \
  --after-probe '["node","/secure/probes/transfer-after-recovery.mjs"]' \
  --evidence /secure/evidence/worker-disruption.json
```

The runner checks that the service is running, pauses only the allow-listed `worker` or `memorycache` service, always unpauses it in a `finally` path, waits for recovery, and writes a redacted phase receipt. Exact confirmation is required to prevent an accidental shared-environment disruption.

## Worker metrics

Worker and scheduler processes expose `/metrics` only on the private `athyper-platform-observability` network. The controller writes one Prometheus file-discovery document per running instance and removes it on instance shutdown. Useful acceptance queries include:

```promql
athyper_record_transfer_operations_total
athyper_record_transfer_queue_delay_seconds_count
athyper_record_transfer_retries_total
athyper_record_transfer_rows_total
```

The endpoints are deliberately absent from the public gateway. A running instance is not operationally qualified until the `worker` and `scheduler` targets are up and carry the `instance`, `environment`, `service`, and `source_revision` labels.
