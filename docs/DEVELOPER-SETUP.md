# Developer Local Setup Guide

This guide gets you from a fresh clone to a running local development environment.

## Prerequisites

| Tool           | Version     | Notes                                                                                  |
| -------------- | ----------- | -------------------------------------------------------------------------------------- |
| Node.js        | >= 20 (LTS) |                                                                                        |
| pnpm           | >= 9        |                                                                                        |
| Docker Desktop | Compose v2  | Ensure Docker is running before Step 3                                                 |
| Git            | any         |                                                                                        |
| mkcert         | any         | Required for local TLS certificates ([install](https://github.com/FiloSottile/mkcert)) |

## 1. Clone and Install

```bash
git clone <repo-url> athyper
cd athyper
pnpm install
```

## 2. Hosts File

Add these entries to your hosts file (requires admin/sudo):

- **Windows**: `C:\Windows\System32\drivers\etc\hosts`
- **macOS / Linux**: `/etc/hosts`

```
127.0.0.1 gateway.mesh.athyper.local
127.0.0.1 iam.mesh.athyper.local
127.0.0.1 objectstorage.mesh.athyper.local
127.0.0.1 objectstorage.console.mesh.athyper.local
127.0.0.1 telemetry.mesh.athyper.local
127.0.0.1 metrics.mesh.athyper.local
127.0.0.1 traces.mesh.athyper.local
127.0.0.1 logs.mesh.athyper.local
127.0.0.1 neon.athyper.local
127.0.0.1 api.athyper.local
```

## 3. Generate TLS Certificates

The gateway (Traefik) terminates TLS with locally-trusted certificates generated by mkcert.

```bash
# Windows
cd mesh/scripts
./generate-mesh-certs.bat

# macOS / Linux
cd mesh/scripts
./generate-mesh-certs.sh
```

This does two things:

1. **Installs the mkcert CA** into your system/browser trust store (`mkcert -install`) — so your browser trusts `*.mesh.athyper.local` certificates without warnings
2. **Generates certificate files** under `mesh/config/gateway/certs/` for the Traefik gateway

> **Important**: Every developer must run this on their own machine. The cert files may already exist in the repo, but the CA trust is per-machine — without it, your browser will silently block redirects to `https://iam.mesh.athyper.local` (e.g., the Keycloak login redirect won't work). Restart your browser after running the script.

## 4. Set Up Environment File

Create the `.env` file that Docker Compose uses. The setup script copies the correct template for your environment:

```bash
# Windows
cd mesh/scripts
./setup-env.bat local

# macOS / Linux
cd mesh/scripts
./setup-env.sh local
```

This creates `mesh/env/.env` from `mesh/env/local.env.example`. If you prefer to do it manually:

```bash
cp mesh/env/local.env.example mesh/env/.env
```

> **Note**: Without this step, you must pass `--env-file ../env/.env.example` to every `docker compose` command.

## 5. Initialize Data Directories

Create the required data directories for persistent volumes:

```bash
# Windows
cd mesh/scripts
./init-data.bat

# macOS / Linux
cd mesh/scripts
./init-data.sh
```

This creates the directory structure under `mesh/data/` (db, memorycache, objectstorage, telemetry).

## 6. Start Docker Mesh

The mesh runs all infrastructure services (PostgreSQL, Redis, Keycloak, MinIO, Traefik, telemetry).

```bash
# Windows
cd mesh/scripts
./up.bat

# macOS / Linux
cd mesh/scripts
./up.sh
```

Or, using docker compose directly:

```bash
cd mesh/compose
docker compose --env-file ../env/.env --profile mesh up -d
```

Wait for all services to become healthy:

```bash
cd mesh/compose
docker compose --env-file ../env/.env ps
```

All services should show `(healthy)`. Keycloak (IAM) takes the longest — allow ~30 seconds.

> **Important**: Always pass `--env-file` when running `docker compose` commands directly. Without it, environment variables are unset and all services will fail.

## 7. Seed the Application Database

The PostgreSQL init script creates two databases automatically on first start:

- `athyper_dev1` — application database
- `athyperauth_dev1` — Keycloak database

Seed the application database with reference data:

```bash
# Windows
cd mesh/scripts
./seed-db.bat

# macOS / Linux
cd mesh/scripts
./seed-db.sh
```

Options:

- `--no-demo` — production-like seed (DDL + reference data, no demo data)
- `--demo-only` — demo data only (requires standard data already seeded)
- `--reset` — drop all schemas and re-seed from scratch
- `--status` — show current provision status

## 8. Initialize Keycloak Realm

Import the realm configuration (users, clients, roles) into Keycloak:

```bash
# Windows
cd mesh/scripts
./initdb-iam.bat

# macOS / Linux
cd mesh/scripts
./initdb-iam.sh
```

This imports the `athyper` and `platform-control` realms. The script waits 5 seconds before executing — press Ctrl+C to cancel.

## 9. Configure Neon Web App

```bash
cd products/neon/apps/web
cp .env.example .env.local
```

The `.env.example` is pre-configured for local development with the Docker mesh. **In most cases you don't need to change anything.**

### Key Variables

| Variable                       | Value                                                                | Purpose                                    |
| ------------------------------ | -------------------------------------------------------------------- | ------------------------------------------ |
| `REDIS_URL`                    | `redis://:athyperadmin@localhost:6379/0`                             | Session storage (mesh Redis with password) |
| `DATABASE_URL`                 | `postgresql://athyperadmin:athyperadmin@localhost:6432/athyper_dev1` | Tenant resolution via PgBouncer            |
| `KEYCLOAK_BASE_URL`            | `https://iam.mesh.athyper.local`                                     | Keycloak via Traefik gateway               |
| `KEYCLOAK_REALM`               | `athyper`                                                            | Keycloak realm name                        |
| `KEYCLOAK_CLIENT_ID`           | `neon-web`                                                           | Web app client registered in Keycloak      |
| `RUNTIME_API_URL`              | `https://api.athyper.local`                                          | Runtime API via Traefik gateway            |
| `NODE_TLS_REJECT_UNAUTHORIZED` | `0`                                                                  | Accept self-signed certs (local only!)     |

## 10. Start Development Server

```bash
cd products/neon/apps/web
pnpm dev
```

The app runs at `http://localhost:3001`.

## Quick Reference — Script Summary

All scripts are in `mesh/scripts/`. Use `.bat` on Windows, `.sh` on macOS/Linux.

| Script                | Purpose                              | When to Run                                 |
| --------------------- | ------------------------------------ | ------------------------------------------- |
| `setup-env`           | Create `mesh/env/.env` from template | Once (first setup)                          |
| `setup-config`        | Create kernel config from template   | Once (first setup)                          |
| `generate-mesh-certs` | Generate TLS certificates via mkcert | Once (first setup)                          |
| `init-data`           | Create/reset data directories        | Once, or to reset all data                  |
| `up`                  | Start the Docker mesh stack          | Every time you need infrastructure          |
| `down`                | Stop the Docker mesh stack           | When done developing                        |
| `seed-db`             | Seed application database            | Once (first setup), or `--reset` to re-seed |
| `initdb-iam`          | Import Keycloak realm configuration  | Once (first setup), or after realm changes  |
| `export-iam`          | Export current Keycloak realm        | When saving realm changes                   |
| `logs`                | Tail Docker mesh logs                | As needed for debugging                     |

## Troubleshooting

### "variable is not set" warnings from docker compose

**Cause**: Running `docker compose` without `--env-file`.

**Fix**: Always specify the env file:

```bash
docker compose --env-file ../env/.env ps
```

Or run `setup-env.bat local` to create the `.env` file, then use the `up`/`down` scripts which handle this automatically.

### "ECONNREFUSED" or "Connection refused" on login

**Cause**: Keycloak is not reachable at `https://iam.mesh.athyper.local`.

**Fix**:

1. Verify hosts file entries are present
2. Verify Docker mesh is running: `docker compose --env-file ../env/.env ps`
3. Verify Keycloak container is healthy: `docker logs athyper-mesh-iam-1`

### "database does not exist"

**Cause**: The `init-databases.sh` entrypoint didn't execute (can happen if the data directory was initialized before configs were correctly mounted).

**Fix**:

```bash
# Connect to the running db container and create the databases manually
docker exec athyper-mesh-db-1 psql -U athyperadmin -d postgres -c "CREATE DATABASE athyper_dev1;"
docker exec athyper-mesh-db-1 psql -U athyperadmin -d postgres -c "CREATE DATABASE athyperauth_dev1;"
```

Or reset everything: stop the mesh, run `init-data` to wipe data, then start the mesh again.

### "Cannot determine database password"

**Cause**: The script can't find `mesh/env/.env`.

**Fix**: Run `setup-env.bat local` (or `setup-env.sh local`) to create the `.env` file from the template. The scripts fall back to `.env.example` but having a `.env` file avoids this issue entirely.

### "Invalid or expired state parameter" on callback

**Cause**: Redis session expired or is unreachable.

**Fix**:

1. Check Redis is running: `docker compose --env-file ../env/.env ps | grep memorycache`
2. Check `REDIS_URL` in `.env.local` includes the password: `redis://:athyperadmin@localhost:6379/0`
3. The old default `redis://localhost:6379/0` (no password) does NOT work with the Docker mesh Redis

### "realm not found" or 404 from Keycloak

**Cause**: `KEYCLOAK_REALM` doesn't match the imported realm.

**Fix**:

1. Verify `KEYCLOAK_REALM=athyper` in `.env.local` (not `neon-dev`)
2. Re-run the realm import: `cd mesh/scripts && ./initdb-iam.sh`

### Tenant resolution returns null / "default"

**Cause**: `DATABASE_URL` is not set in `.env.local`.

**Fix**: Add `DATABASE_URL=postgresql://athyperadmin:athyperadmin@localhost:6432/athyper_dev1` to `.env.local`.

### Collaboration / comments routes return 500

**Cause**: `API_MESH_URL` is not set.

**Fix**: Add `API_MESH_URL=https://api.athyper.local` to `.env.local`.

### Login button does nothing / browser stuck on redirect

**Cause**: Clicking "Sign in with Keycloak" redirects to `https://iam.mesh.athyper.local`, but the browser silently refuses to connect because it doesn't trust the self-signed TLS certificate.

**Fix**:

1. **Run the cert generator** (if you haven't already). This installs the mkcert CA into your system trust store:

   ```bash
   # Windows
   cd mesh/scripts
   ./generate-mesh-certs.bat

   # macOS / Linux
   cd mesh/scripts
   ./generate-mesh-certs.sh
   ```

   The script calls `mkcert -install` which adds the local CA to your browser's trust store. **Each developer must run this on their own machine** — the generated `.crt`/`.key` files in the repo are not enough; the CA must be installed locally.

2. **Restart your browser** after running the script (some browsers cache certificate decisions).

3. If it still doesn't work, verify the CA is installed by opening `https://iam.mesh.athyper.local` directly — you should see the Keycloak page without any certificate warning. If you see a warning, click "Advanced" → "Proceed" as a temporary workaround, then re-run `mkcert -install`.

### TLS / certificate errors

**Cause**: The mesh gateway uses self-signed certificates.

**Fix**: Ensure `NODE_TLS_REJECT_UNAUTHORIZED=0` is set in `.env.local`. This is **local development only** — never use in staging/production.

### Container keeps restarting with "is a directory" error

**Cause**: On Docker Desktop for Windows, if a config file doesn't exist at the mount source path when a container starts, Docker creates an empty directory instead of failing. The container then can't read the "file" because it's actually a directory.

**Fix**:

1. Stop the mesh: `cd mesh/scripts && ./down.bat`
2. Delete any auto-created directories under `mesh/data/` that look like files (e.g., `config.yml` as a directory)
3. Verify the actual config files exist under `mesh/config/`
4. Restart the mesh: `./up.bat`

## Environment Architecture

```
┌─────────────────────────────────────────────────────┐
│  Your Machine (localhost)                           │
│                                                     │
│  ┌──────────────┐     ┌──────────────────────────┐  │
│  │ Neon Web App  │     │ Docker Mesh              │  │
│  │ (pnpm dev)   │     │                          │  │
│  │ :3001        │────▶│ Traefik Gateway (:443)   │  │
│  │              │     │  ├─ iam.mesh.athyper.local│  │
│  │ .env.local   │     │  ├─ api.athyper.local    │  │
│  │              │     │  └─ objectstorage.mesh.…  │  │
│  │              │     │                          │  │
│  │              │────▶│ Redis (:6379)            │  │
│  │              │────▶│ PgBouncer (:6432)        │  │
│  └──────────────┘     │ PostgreSQL (:5432)       │  │
│                       │ MinIO (:9000)            │  │
│                       │ Keycloak                 │  │
│                       └──────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

### File Map

| File                                                          | Purpose                                                   | Used By                     |
| ------------------------------------------------------------- | --------------------------------------------------------- | --------------------------- |
| `mesh/env/.env.example`                                       | Docker Compose env template (local)                       | `setup-env` script          |
| `mesh/env/.env`                                               | Active Docker Compose env (created from template)         | `docker compose --env-file` |
| `mesh/env/staging.env.example`                                | Docker Compose env template (staging)                     | CI/CD                       |
| `mesh/env/production.env.example`                             | Docker Compose env template (production)                  | CI/CD                       |
| `mesh/config/`                                                | Infrastructure config files (DB, gateway, telemetry, IAM) | Docker volume mounts        |
| `mesh/data/`                                                  | Persistent data directories (DB, Redis, MinIO, telemetry) | Docker volume mounts        |
| `mesh/config/apps/athyper/kernel.config.local.parameter.json` | Runtime kernel config (local)                             | athyper-runtime container   |
| `mesh/config/apps/athyper/kernel.config.schema.json`          | JSON Schema for kernel config                             | IDE validation              |
| `products/neon/apps/web/.env.example`                         | Neon web app env template                                 | `cp` to `.env.local`        |

### Variable Name Differences

The mesh (Docker) and web app (localhost) use **different variable names** for the same infrastructure:

| Concept      | Mesh Env Var                      | Web App Env Var                 | Why Different                                   |
| ------------ | --------------------------------- | ------------------------------- | ----------------------------------------------- |
| Keycloak URL | `IAM_ISSUER_URL`                  | `KEYCLOAK_BASE_URL`             | Mesh needs full issuer URL; web needs base only |
| Realm        | `IAM_DEFAULT_REALM`               | `KEYCLOAK_REALM`                | Different config loaders                        |
| API Client   | `IAM_CLIENT_ID=athyper-api`       | `KEYCLOAK_CLIENT_ID=neon-web`   | Different Keycloak clients                      |
| Redis        | `redis://:pw@memorycache:6379`    | `redis://:pw@localhost:6379`    | Docker hostname vs localhost                    |
| Database     | `postgresql://…@dbpool-apps:6432` | `postgresql://…@localhost:6432` | Docker hostname vs localhost                    |
| API URL      | `PUBLIC_BASE_URL`                 | `RUNTIME_API_URL`               | Mesh is the API; web calls the API              |
