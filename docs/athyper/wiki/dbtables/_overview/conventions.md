# Naming Conventions & Patterns

## Table Naming

| Pattern          | Example                             | Rule                            |
| ---------------- | ----------------------------------- | ------------------------------- |
| Schema-qualified | `core.tenant`                       | Always use `schema.table`       |
| Snake case       | `principal_role`                    | All lowercase, underscores      |
| Singular nouns   | `core.principal` (not `principals`) | Tables named as singular entity |
| Junction tables  | `core.group_member`                 | Both entities joined            |

## Column Patterns

### Standard Audit Columns

Every table includes these trailing columns:

```sql
created_at    timestamptz NOT NULL DEFAULT now(),
created_by    text NOT NULL,
updated_at    timestamptz,
updated_by    text
```

Some tables omit `updated_at`/`updated_by` when they are append-only (audit logs, transitions).

### Tenant Scoping

```sql
tenant_id     uuid NOT NULL REFERENCES core.tenant(id) ON DELETE CASCADE
```

Always the first FK column after the primary key.

### Primary Keys

```sql
id            uuid PRIMARY KEY DEFAULT gen_random_uuid()
```

All tables use UUID v4 primary keys generated by `pgcrypto`.

Exception: Partitioned tables include the partition key in the PK:

```sql
PRIMARY KEY (id, event_timestamp)   -- audit.workflow_event_log
PRIMARY KEY (id, created_at)        -- notify.notification, notify.delivery
```

### Status Columns

```sql
status        text NOT NULL DEFAULT '<default_value>',
CONSTRAINT <table>_status_chk CHECK (status IN ('value1','value2',...))
```

Status enums are enforced via CHECK constraints, not database ENUM types (more flexible for evolution).

### Soft Delete

```sql
deleted_at    timestamptz,      -- NULL = active, non-NULL = soft-deleted
deleted_by    text
```

Used in: `ui.saved_view`, `collab.entity_comment`, `collab.message`, `doc.attachment_comment`

### JSONB Columns

| Column Name     | Purpose                                        |
| --------------- | ---------------------------------------------- |
| `metadata`      | Extensible key-value store for future fields   |
| `config`        | Configuration object                           |
| `definition`    | Complex structured data (workflow rules, etc.) |
| `compiled_json` | Precompiled snapshots for runtime performance  |
| `payload`       | Event/request payload                          |
| `details`       | Freeform detail information                    |

## Constraint Naming

| Type        | Pattern                   | Example                |
| ----------- | ------------------------- | ---------------------- |
| Primary key | `<table>_pkey` (implicit) | `tenant_pkey`          |
| Check       | `<table>_<column>_chk`    | `tenant_status_chk`    |
| Unique      | `<table>_<columns>_uniq`  | `entity_name_uniq`     |
| Foreign key | `fk_<table>_<target>`     | `fk_customer_industry` |
| Exclusion   | `<table>_<desc>_excl`     | (not currently used)   |

## Index Naming

| Type     | Pattern                                  | Example                       |
| -------- | ---------------------------------------- | ----------------------------- |
| Standard | `idx_<table>_<columns>`                  | `idx_tenant_realm_key`        |
| Partial  | `idx_<table>_<columns>` + `WHERE` clause | `idx_mfa_config_enabled`      |
| GIN      | `idx_<table>_<column>`                   | `idx_product_tags`            |
| Covering | `idx_<table>_<desc>` + `INCLUDE(...)`    | `idx_security_event_timeline` |
| Unique   | `idx_<table>_<desc>_uniq`                | `idx_entity_short_uniq`       |

### Index Strategy

1. **Tenant-first composite indexes** for all business queries
2. **Partial indexes** with `WHERE` clauses for filtered scans (e.g., `WHERE is_active = true`)
3. **GIN indexes** for `jsonb`, `text[]`, and `tsvector` columns
4. **Covering indexes** (`INCLUDE`) on audit tables for index-only timeline scans
5. **Descending** on timestamp columns for recent-first queries

## Foreign Key Patterns

### Cascading Deletes

```sql
REFERENCES core.tenant(id) ON DELETE CASCADE      -- Tenant deletion cleans everything
REFERENCES parent_table(id) ON DELETE CASCADE      -- Parent-child relationships
```

### Restrict Deletes

```sql
REFERENCES wf.lifecycle(id) ON DELETE RESTRICT     -- Cannot delete lifecycle with active instances
REFERENCES core.operation(id) ON DELETE RESTRICT   -- Cannot delete operations referenced by rules
```

### Set Null

```sql
REFERENCES core.principal(id) ON DELETE SET NULL   -- Actor references survive principal deletion
REFERENCES ent.employee(id) ON DELETE SET NULL      -- Manager reference nullified
```

### Deferred FKs

Used for circular references:

```sql
CONSTRAINT ... DEFERRABLE    -- principal.external_id, mfa_config.principal_method_uniq
```

## Timestamp Precision

| Context                                  | Precision                                       |
| ---------------------------------------- | ----------------------------------------------- |
| Standard tables                          | `timestamptz` (microsecond, PostgreSQL default) |
| High-volume tables (collab, notify, doc) | `timestamptz(6)` (explicit microsecond)         |
| Partitioned tables                       | `timestamptz` (partition key)                   |

## Version Columns

### Optimistic Concurrency

```sql
version       int NOT NULL DEFAULT 1    -- Incremented on each update
```

Used in: `meta.overlay`, `ui.saved_view`

### Content Versioning

```sql
version_no    int NOT NULL DEFAULT 1    -- Monotonically increasing per parent
```

Used in: `meta.entity_version`, `meta.permission_policy_version`, `doc.template_version`
