### Proposed contract semantics

The following are design requirements, not accepted JSON members to insert into current closed schemas. Final schema version and exported names belong to implementation review.

1. **Explicit target binding.** Each declared plane maps each supported operation to an exact optional permission, required policy references, registered handler/resolver and storage/provider contract. Every selected binding carries source release identity/hash. Reject duplicate/conflicting/missing target entries and broken defined permission references. Do not derive codes from entities, folders, operations or plane names. An intentionally omitted permission in an otherwise valid binding requires no entity permission grant; null, blank strings, unresolved placeholders and missing target configuration are invalid.
2. **Explicit surface admission.** Bind a stable metadata surface key to supported operations and a declared admission mode: independent directory, current-principal self, parent relationship or lookup projection. This supplements existing published profile surfaces rather than replacing them. Define required server context and projection for that mode. Each operation must have an unambiguous admission contract; if directory and scoped variants differ, declare separate metadata operation bindings rather than letting the caller select permission behavior for the same unrestricted API.
3. **Self scope.** Resolve principal and tenant from refreshed verified context. Enforce the record/child relation in the query or owning transaction, not after returning data. Reject client substitution of principal/tenant. Administrative reads/writes use their own declared surface and bindings. Preserve supported create/patch concurrency and existing independent platform controls.
4. **Parent scope.** Resolve parent entity, record, relationship, target and release/hash through published metadata. Authorize the parent with its exact operation binding, then AND tenant/record/company constraints with the child's baseline constraints. Scope applies to list/count/search/detail/lookup/print and other supported outputs. A copied child URL must retain verifiable parent admission or pass the independent target surface; no parent coordinate may weaken the latter. Cache keys include plane, tenant, principal/admission context, release hashes and relationship scope.
5. **Shared-record write authority.** Distinguish link/use changes from canonical Person/Address/Contact edits. Parent access alone never authorizes mutations affecting other owners. Select the owning domain handler through registered contracts and retain authorization, policy, transaction, audit, concurrency and idempotency controls. Unsupported direct Edit stays unavailable; request_change remains its own governed operation.
6. **Policy and projection.** Apply exact field reveal, resource action and target-reference requirements independently of parent read. Preserve explicit denies, masking and query-use restrictions in server projections. Missing required policy/evaluator fails closed. Keep existing MFA requirements and behavior unchanged; no MFA design or implementation change is authorized here.
7. **Presentation.** Declare readable identity, non-UUID eligible columns, navigation groups, section behavior/order and supported controls in metadata. Validate default/saved/embedded/card/search/scope-label presentation before activation. No UUID fallback, inferred Overview tab or first-field identity. Required parent labels must resolve from an authorized readable projection; inability to do so is an actionable configuration error, not a technical-ID display.
