## Execution and evidence

`pnpm verify:ci-database` owns a uniquely named Docker network, PostgreSQL container with tmpfs storage and PgBouncer container. It accepts no deployed database URL or existing target. Ports bind only to loopback; credentials are generated per run. Cleanup runs on normal success/failure. It applies full ordered foundations sequentially, verifies nonzero provisioning receipts and seed convergence, then seeds two tenants and an additional same-tenant principal. Every discovered PostgreSQL file must have an explicit fixture disposition in the runner. Unknown files, missing reports and zero-test selections fail. Administrative catalog checks are distinct from runtime-role behavioral checks.

`artifacts/ci-integrity/database.json` binds the commit and a source-content fingerprint, including uncommitted relevant files. Required check names, provisioning receipts and nonempty zero-skip test evidence are validated before qualification. A changed source, missing report, failed command or skipped service suite cannot qualify. Reports are uploaded even on failure. Raw local logs are not committed.

The static permission job is independent of the broad quality job. Its independent checks continue after a check fails, preserving the job's failure status. Provisioning and DB verification remain sequential. Existing aggregate job IDs are preserved; actual GitHub merge rules must be verified separately.
